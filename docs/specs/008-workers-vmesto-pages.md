# ТЗ 008 — Workers вместо Pages

Статус: в работе · Приоритет: 1 · Дата: 2026-09-04

## Зачем

В ТЗ 006 хостингом были выбраны Cloudflare Pages. На практике в аккаунте
владельца мастер создания Pages-проекта из дашборда убран: «Create application»
ведёт сразу в Workers, вкладки Pages нет. Прямая ссылка на мастер Pages тоже
не помогла.

Спорить с платформой дороже, чем переехать: Cloudflare уже год ведёт всех
в Workers, и документация описывает миграцию как рекомендуемое направление.
Раз выбор всё равно сделан за нас — делаем его сознательно и сразу.

## Что делаем

`functions/api/lead.js` был написан в формате Pages Functions: файловая
маршрутизация, обработчик `onRequestPost`. В Workers маршрутов по именам файлов
нет, поэтому:

1. `worker/index.js` — один вход, `export default { fetch }`. Внутри проверка
   пути: всё, кроме `POST /api/lead`, отдаёт 404
2. `wrangler.jsonc` — `assets.directory: ./site`, `html_handling:
   auto-trailing-slash` (адреса вида `/ritual/` находят `ritual/index.html`),
   `not_found_handling: none`
3. `functions/` удалена — два источника правды хуже одного
4. `wrangler` добавлен в devDependencies, чтобы сборка была воспроизводимой

Порядок обработки: Cloudflare сначала ищет файл в `site/`, и только если
не нашёл — зовёт Worker. Поэтому статика не проходит через код вообще,
а `/api/lead` доходит до обработчика.
