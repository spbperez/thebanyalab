# ТЗ 009 — Отличать «ещё не собрали» от «не относится к этому бизнесу»

Статус: сделано 2026-09-04 · Приоритет: 1 · Дата: 2026-09-04
Файлы: client.json, scripts/build.mjs, scripts/check.mjs
Зависит: 006, 008

## Зачем

Первая сборка на Cloudflare остановилась на десяти незаполненных полях. Механика
сработала правильно, но список врал: половина этих полей к бане на лодке
не относится вообще и никогда не будет заполнена.

Адреса приёма нет — судно стоит в марине, гостя ведут на борт, а не на улицу
с номером дома. Часов приёма нет — сессии идут по заявке, а не по расписанию.
Профиля в Google пока не существует, отзывов тоже. Требовать их значит держать
сборку красной вечно и приучить всех игнорировать красный цвет.

Пустое поле должно означать одно из двух, и это надо различать: **данных ещё
нет** — сборка стоит; **поле не относится к делу** — сборка идёт.

## Что делаем

В `client.json` появился список `_optional` и рядом `_optionalWhy` — по строке
причины на каждое поле. Генератор и проверки останавливаются только на том,
чего нет в списке. В разметке `openingHoursSpecification` требуется, лишь если
часы заданы.

Список сознательно короткий и объяснённый: `_optional` без причины —
это способ спрятать дыру, а не описать устройство бизнеса.

## Результат

Блокирующих полей осталось два: `business.phone` и `business.phoneDisplay`.
Всё остальное либо заполнено, либо помечено как неприменимое с причиной.

## Критерии готовности

- [x] Списки заведены, генератор и проверки их читают
- [x] Сборка называет только настоящие блокировки
- [x] Каждое неприменимое поле снабжено причиной
