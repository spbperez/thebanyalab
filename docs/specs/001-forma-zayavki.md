# ТЗ 001 — Приём заявки без базы данных

Статус: сделано 2026-09-02 · Приоритет: 1 · Дата: 2026-09-02
Файлы: functions/api/lead.js, templates/apply.html, client.json → apply
Зависит: ничего

## Зачем

Клиенту нужно оставить заявку с сайта. Хранилища на этом уровне нет и не планируется:
база, админка и учёт работ — отдельный продукт, который делается месяцами, а сайт
нужен за день. Смешав их, не получишь ни того, ни другого.

## Что делаем

Форма: имя, телефон, email, сколько человек, когда удобно, свободное поле.
Поток: honeypot → валидация → телефон к E.164 → Telegram → email → редирект на `/thanks`.

**Email у клиента спрашиваем** — вопреки общему правилу конвейера. Здесь он нужен
для дела: письмо от компании со ссылкой на оплату и есть тот артефакт доверия,
которого клиентам сейчас не хватает. Инстаграм такого дать не может.

**Два независимых канала обязательны.** Без базы заявка живёт только в момент
отправки. Если единственный канал упал, заявка потеряна и никто об этом не узнает.
Telegram — карман владельца, клиент про него не знает и ссылок на него не видит:
в США мессенджер покрывает только экспатов из СНГ.

## Чего НЕ делаем

Базы заявок · админки · логина · CRM · Turnstile до появления спама (внешний скрипт
и потеря конверсии авансом; honeypot стоит ноль и закрывает примитивных ботов).

## Критерии готовности

- [x] Функция принимает POST, honeypot молча уводит на `/thanks`
- [x] Телефон приводится к E.164, невалидный отклоняется с понятным текстом
- [x] Оба канала уходят параллельно, падение одного не роняет заявку
- [x] Падение обоих — 502 и запись в лог, клиенту предложен инстаграм
- [ ] Сквозной путь проверен на живом телефоне владельца
