# The Banya Lab — сайт

Статический сайт. Ни одной цифры мимо `client.json`.

```
client.json  ──►  scripts/build.mjs  ──►  site/  ──►  git push  ──►  Cloudflare Pages
```

## Команды

    npm run build        собрать. Падает, если в client.json есть незаполненные поля
    npm run build:draft  собрать черновик с прочерками вместо пустых полей — только для просмотра
    npm run check        проверки перед выкаткой. Их же гоняет CI
    npm run preview      однофайловый просмотр всего сайта, открывается без сервера
    bash scripts/state.sh  где стоим: ТЗ, незаполненные данные, состояние git

## Решения

Каждое принятое решение лежит отдельным файлом в `docs/specs/` с машиночитаемой
шапкой. Старые записи **не переписываются задним числом**: передумали — новый
номер со ссылкой на старый. Иначе теряется единственное, ради чего это ведётся —
возможность через полгода понять, почему решили именно так.

## Что где

    client.json          единственный источник данных
    verified.json        цифры, подтверждённые источником. check.mjs сверяет
    templates/           шаблоны. {{путь}} · {{> _partial}} · {{#each массив}}…{{/each}}
    assets/css/theme.css единственное, что правится визуально под клиента
    assets/img/          настоящие фото с объектов
    site/                генерируется. Руками не трогать
    functions/api/lead.js приём заявки: honeypot → валидация → Telegram + email → /thanks
    docs/specs/          ТЗ и записи решений, по одному файлу на решение
    docs/DESIGN.md       визуальное решение и почему именно оно
    docs/SETUP.md        порядок запуска
    docs/INTAKE.md       чеклист сбора данных
    docs/PHOTOS.md       что снимать и в каких пропорциях
    docs/CONTENT-PLAN.md план библиотеки ответов и границы того, что пишем

## Чего здесь нет и не будет

Базы заявок · админки · логина · CRM · календаря бронирования · фреймворков ·
выдуманных рейтингов, отзывов и лицензий · стоковых фото людей.

Если что-то из этого понадобится — заводится отдельным репозиторием и отдельным ТЗ.

## Почему site/ не в репозитории

`site/` генерируется из `client.json` и собирается Cloudflare Pages при каждом
пуше. Держать сгенерированное в git — значит однажды поправить данные, забыть
сборку и выкатить старое. Локально это ловит `npm run check`, сверяя `site/`
с хешем `client.json`; в CI сборка идёт первой, поэтому расхождению взяться
неоткуда.
